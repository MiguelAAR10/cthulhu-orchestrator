Setup: a scratch clone with the orq-clon marker on slice/01, the real `Evaluate`/`RepoPropio` called from a temporary test (now deleted, tree clean), and real bash with git 2.43.0. `go test ./internal/gate` passes.
**Holds:** every bypass in 7b is denied: `log --format="$f"`, `log -1 -m $O`, `-F $O`, `show -m $O`, `--grep -m $O`, `--format "$O"`, `log -1 -m *`, `branch -m "$X"`, `commit -m -m $O`. These are also denied: `commit $X`, `-m "$x" -a $Y`, `--message "$x" "$y"`, `-mF "$x"`, `-Fm "$x"`, `--mess "$x"`, `--fixup/--squash "$x"`, `commit -m x *|-*|[-]*`, `git -C . commit $X`, `git -C "$d"`, `--git-dir="$g"`, `git $S`, the alias `git ci` and `-c alias.ci=commit`, and `checkout -b|switch|branch "$b"`.
**Legit flow holds:** `commit -m "$msg"`, `-am "$m"`, `-m "$(cat <<'EOF' … EOF)"` (gate and real bash), `--file="$f"`, `-C/-c "$x"`, `--date="$d"`, `add -A`, `diff -- "$F"`, `log -- "$F"`, `status`, and switch/branch/commit on `slice/01`.
**FAILS: a dynamic word becomes a `git commit` option.** `opcionValor` (harness/internal/gate/repo.go:316, :325) knows only `--message/--file/--author/--date` and the letters `mFCc`. Git's other value-taking commit options swallow the gate's assumed option, so the next dynamic word is free:
- Short clusters, repo.go:325. The scan finds a trailing `m` but ignores an earlier letter that takes the rest of the word: `-t` (template), `-S` (key id) or `-u` (mode). Repro: `printf x > m; git add a.txt; O=--message=INJECTED; git commit -tm "$O"`. Gate: ALLOW. Git: commit subject `INJECTED`, so `$O` was parsed as an option, not a message. `git commit -Sm "$O"` is also ALLOWed: git reads `-S` with key `m`, and `$O` is free.
- Long options, repo.go:316/:293. A long option with a required value that the gate does not know eats the literal `-m`. The gate then lets the next word through as `-m`'s value. Repro: `O=--message=INJECTED; git commit --template -m "$O"` (with a file `./-m` present) or `git commit --trailer -m "$O"`. Gate: ALLOW. Git: subject `INJECTED`. `--cleanup -m "$O"` and `--fixup -m "$O"` are also ALLOWed; git 2.43 exits on those before committing.
Impact today is low, because a worker can type these commit options literally and the gate checks nothing commit-specific. But it breaks the stated invariant ("dynamic only as values of commit options"). Any later commit check (`--amend`, pathspecs, `--pathspec-from-file`) could be bypassed this way.
Fix direction: in clusters, stop at the first letter that takes a value (`m F C c t S u`) and consume only if that letter is `mFCc` and is last. When the previous literal word is an unknown value-taking long option (`--template --trailer --cleanup --fixup --squash --reuse-message --reedit-message --pathspec-from-file`), treat it as consuming the next word. Simplest: deny the dynamic word whenever it follows anything other than a known consumer.
VERDICT: fix
