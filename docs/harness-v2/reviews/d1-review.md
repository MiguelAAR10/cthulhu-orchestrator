# D1 review (22fbc44..fa2eac7), independent

Ran `go test ./internal/{cli,slice,app}` (ok) plus a throwaway fixture test on `Metricas`, since deleted. The page does not claim "paso" falsely: it reads the sealed receipt via `reciboConfiable` (contrato.go:158), which only accepts `paso`. The median arithmetic, the empty and even cases, the `desde` filter and double-stamp protection are correct. Defects found:

1. **Re-verifying a VERIFICADO slice restarts the clock, so the median comes out too low.** `Verificar` accepts VERIFICADO (nucleo.go:299), and metricas.go:129 overwrites `verificado[slice]` on every `paso`. Repro journal: paso 10:00, paso 10:30, decision 10:40. Reported median is 10 min; the Owner actually waited 40 min. The 24 h count is affected too: re-verifying a stale slice resets it to 0. Fix: keep the first `paso` while the slice stays VERIFICADO.
2. **VERIFICADO→BLOQUEADO does not stop the clock, so the 24 h count comes out too high.** A re-verify from VERIFICADO can call `bloquear` (nucleo.go:318/328/351, tamper paths), which journals `fase De=VERIFICADO A=BLOQUEADO`. metricas.go:135 stops the clock only for `A==IMPLEMENTANDO` or `CERRADO`. Repro: paso at T, then that fase event, then `Metricas(now=T+48h)` gives `SinDecidir24h=1`. That slice is with the Orchestrator, not the Owner, and `orq status`/`Esperando` correctly does not list it, so the number and the status disagree. Fix: stop on any `De==VERIFICADO` transition other than to INTEGRANDO.
3. **The page mixes two commits.** `Pagina` (slice/pagina.go:37) builds "Archivos" from `Alinear`, which diffs red→the *current clone tip* (equipo.go:310-320). "Recibo/Pruebas" describe `rec.Head`. If the worker commits after verification, the page lists unverified files next to a passing receipt with no `!!`. `cerrar --aceptado` then refuses (cierre.go:94), but the page the Owner read was wrong. Fix: diff red→`rec.Head`, or raise `!!` when the tip ≠ `rec.Head`.
4. **The story can belong to another slice.** app/pagina.go:25-38 takes the latest `historia` in the channel, whatever slice it was for. With two slices open from different stories, slice A's page shows B's story under the header "canal: historia ID". The report admits this (d1-report "Design choices"). It is still a wrong field on the page. At minimum, flag it with `!!` when more than one slice is open.
5. **Minor (inflates the median):** the `verificacion` stamp uses `now`, taken *before* the test run (cli/proyecto.go:555 → nucleo.go:401 `TS: now`). With a timeout of up to 600 s, the run time counts against a 10 min target. Stamp the event with `time.Now()` after the run.

Two hints that only print text still suggest `orq slice reintentar "qué cambia"` without `--causa` (slice/slice.go:382, app/relevo.go:92). Following them hits a usage error.
