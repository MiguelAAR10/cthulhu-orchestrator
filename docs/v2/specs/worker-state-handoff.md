# Spec — worker state, watcher, `orq handoff`, memory sync

Roadmap: slice 5 (event-driven status), slice 4 (revive), Owner requirements 2026-11-08.

## What the Owner gets

Every worker keeps one small file that says what it is doing and whether it is alive. Code, not an LLM, watches those files and flags workers that are dead, stuck, or over time. The orchestrator stops relaying "are you done?" messages. `orq handoff` writes one page that lets another person (or a future you) pick the project up. At `orq init` you choose where orq's memory lives: only on this machine, committed with the code, or on a separate `orq/state` branch.

## `.orq/workers/<id>/state.json`

```json
{"schema":"orq.worker/v1","id":"w-s04-t2","slice":"S-04","task":"T2",
 "agent":"claude|codex|...","model":"opus|...","pid":12345,"host":"hostname",
 "worktree":"/abs/path","branch":"orq/S-04-t2",
 "started":"RFC3339","heartbeat":"RFC3339","budget_min":45,
 "phase":"running|asks_verification|blocked|question|exited",
 "exit_code":null,"head":"sha","commits":3,
 "tests":{"added":2,"passing":10,"total":10},
 "context_pct":null,"summary":"one line, plain language","stop":"ST-0003"}
```

- `orq slice lanzar` creates the file with `phase=running`. That command already passes the admission check (slice 2). `pid` is the agent process, or `null` when the runner cannot report it.
- Writes are atomic: write to `state.json.tmp`, then rename. Only the worker (through `orq worker`) and the watcher write the file.
- `head` and `commits` are computed by orq from the worktree (`git rev-list --count <base>..HEAD`). They are never self-reported. `tests` comes from the last runner report (`Recibo.Ejecutados/Fallidos`), or stays `null`. `context_pct` is `null` unless the agent adapter exposes it.

## Commands

```
orq worker beat [--phase running|blocked|question] [--summary "..."] [--context-pct N]
orq worker done --summary "..." [--ask-verification]   # sets phase=asks_verification|exited, exit_code=0
orq worker list [--json]
```

The worker id comes from `ORQ_WORKER_ID`, which `lanzar` sets. `beat` refreshes `heartbeat`, `head`, and `commits`. `--phase blocked` requires an open stopper, whose id is stored in `stop`. `question` posts a message to the channel (`tipo=pregunta`). `done` appends `{"event":"done"}` to `.orq/tasks.jsonl` and marks the plan task `hecha`, but only if the plan's own checks pass.

## Watcher (code, `internal/watch`)

It runs on `orq watch` (one pass) or on a loop. Stale defaults to 10 min (`.orq/config.json` `watch.stale_min`).

| Verdict | Rule |
|---|---|
| `dead` | `pid` is set, the host is the same, and the process does not exist, while phase ∉ {exited, asks_verification} |
| `exited` | phase=exited, or the runner reports an exit. A missing `exit_code` is filled in from the runner if it is known |
| `stuck` | phase=running and now − heartbeat > stale **and** `head` unchanged since the previous pass |
| `timeout` | now − started > `budget_min` × 1.0 (warn) or × 1.5 (act) |
| `ok` | otherwise |

On a verdict change, the watcher appends `{"ts","worker","verdict","reason"}` to `.orq/watch.jsonl` and sends one channel message to the orchestrator (idempotency key `worker+verdict`). On `timeout`-act, it also raises `confirmation/soon`. The watcher never kills a process and never deletes a worktree. Closing them is the job of `orq gc` (slice 2).

## `orq handoff` → `HANDOFF.md` at the repo root (or `--out`)

The file is generated, so it is safe to overwrite. It has a header: "generated by orq at <ts>; do not edit". Sections, ≤ 120 lines in total:
1. What this is: the product goal, taken from the first `requisito` memory item.
2. Status: the `orq board` text output, without color.
3. Open stoppers.
4. How to resume: `orq revive`, then `orq board`, and the active slice and next ready tasks.
5. Where memory lives: the sync mode and its exact commands.
6. Last 5 decisions (memory `tipo=decision`).

It includes no secrets and no absolute paths outside the repo.

## Memory sync policy (`orq init --sync local|commit|branch`, saved as `.orq/config.json` `sync`)

- **local** (default): `.orq/` is added to `.gitignore`. Nothing leaves the machine.
- **commit**: `.orq/` is versioned, except `.orq/workers/`, `*.lock`, `board.html`, and artifact output. Those always stay ignored. The user commits `.orq/` as normal. orq never commits on its own.
- **branch**: `.orq/` is ignored on working branches. `orq sync push` and `orq sync pull` use a separate worktree and never touch the user's HEAD, index, or branches:

```
# push
git worktree add --no-checkout .orq-sync orq/state 2>/dev/null \
  || git worktree add --orphan -b orq/state .orq-sync          # first time
rsync -a --delete --exclude workers/ --exclude '*.lock' .orq/ .orq-sync/orq/
git -C .orq-sync add -A orq && git -C .orq-sync commit -m "orq state <ts>" || true
git push origin orq/state                                      # fast-forward only
git worktree remove .orq-sync
# pull
git fetch origin orq/state
git merge-base --is-ancestor orq/state origin/orq/state  # else stop: "diverged, resolve by hand"
git update-ref refs/heads/orq/state origin/orq/state, then copy orq/ into .orq/ (no overwrite of a newer local file without --theirs)
```

orq never runs `--force` or `+refspec` and never rebases. If a push is rejected, orq runs pull and then retries push once; if it fails again, orq stops and reports. `.orq-sync/` goes in `.gitignore`.

## Acceptance tests

1. **Given** a launched worker, **when** it runs `orq worker beat` after 2 commits, **then** state.json shows `commits=2`, and `head` equals the worktree HEAD, whatever value the worker reported.
2. **Given** heartbeat 11 min old and an unchanged head, **when** `orq watch` runs twice, **then** exactly one `stuck` entry and one channel message are written.
3. **Given** a pid that no longer exists, **when** the watcher runs, **then** the verdict is `dead`, and the worktree and process table are untouched.
4. **Given** `sync=branch`, **when** `orq sync push` runs on a feature branch with uncommitted changes, **then** HEAD, the index, and `git status` are byte-identical before and after, and `orq/state` has a new commit.
5. **Given** a diverged remote `orq/state`, **when** push runs, **then** it exits non-zero with the message "diverged", and no force push happens.
6. **Given** a project with one open stopper, **when** `orq handoff` runs, **then** HANDOFF.md has all 6 sections and contains no string that the stopper secret check rejects.

## Out of scope

Killing or restarting workers automatically, cross-machine pid checks, an encrypted state branch, merging `.orq` conflicts automatically, and getting `context_pct` from agents that do not expose it.
